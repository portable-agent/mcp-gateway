# ADR-0001: MCP Gateway остаётся stateless-маршрутизатором

- Статус: принято
- Дата: 2026-09-09

## Контекст

Workflow должен вызывать разные MCP-сервисы, но не должен знать их URL, transport и особенности ошибок.
Одновременно MCP Gateway не должен превращаться в ещё одно хранилище действий или копию бизнес-логики.

## Решение

Gateway проверяет OIDC, выбирает заранее настроенный маршрут, разрешает tool по allowlist, вызывает его
через официальный MCP SDK и возвращает нормализованный ответ. Состояние действия и retry остаются в
Temporal/action-service, а идемпотентность результата — в конечном MCP-сервисе.

## Последствия

- новый MCP-сервис добавляется конфигурацией и контрактом, без `switch` в коде;
- gateway легко масштабировать, потому что у него нет базы;
- временная MCP-сессия создаёт дополнительную задержку;
- connection pooling добавляется только после измерения, чтобы не усложнять MVP заранее.
