# Runbook

## Health check

```http
GET /health
```

Норма: HTTP 200 и `{"status":"ok"}`.

## Ответы Call API

| Статус | Значение                                   | Что проверить                               |
| ------ | ------------------------------------------ | ------------------------------------------- |
| 400    | Неверная форма запроса                     | UUID action, requestKey и обязательные поля |
| 401    | Токен отсутствует или не прошёл проверку   | issuer, audience, срок, tenant и scope      |
| 403    | Connector или tool отсутствует в allowlist | `MCP_CONNECTORS_JSON`                       |
| 502    | MCP не ответил или вернул tool error       | health целевого MCP, токен и timeout        |
| 500    | Неожиданная внутренняя ошибка              | логи по `x-request-id`, без вывода токена   |

## Gateway не видит Calendar MCP

1. Проверь `/health` обоих сервисов.
2. Проверь URL маршрута внутри того же Docker/Kubernetes network.
3. Проверь, что endpoint заканчивается на `/mcp`.
4. Проверь audience и scope токена на обеих границах.
5. Не увеличивай timeout до поиска причины.

## Масштабирование

Gateway stateless и может масштабироваться горизонтально. Перед увеличением replicas сначала измерь
connection rate и latency MCP handshake: текущая реализация открывает короткую сессию на один вызов.
Пул соединений появится только после baseline-теста, если измерения подтвердят необходимость.
